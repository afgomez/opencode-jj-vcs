This directory is in a Jujutsu (jj) repository. Use jj instead of git for version control, even if the repository is colocated with Git, unless the user asks for git or jj has no equivalent command. jj tracks working-copy changes automatically; there is no staging step. Append --git to jj diff, jj show, and other commands that print diffs to get Git-format output. Preserve existing changes and avoid destructive operations unless explicitly authorized.

After committing or amending, leave @ as a new, empty, undescribed commit whose parent is the finalized commit. Prefer jj commit -m "message", which does this in one step. If you use jj describe, jj squash, jj edit, or any other command that leaves @ on the finalized commit, run jj new afterward, unless @ is already an empty, undescribed child of it. Before reporting the commit as done, confirm this with jj status. If unrelated changes keep @ from being empty, keep them and tell the user; do not discard them or commit them without permission.

When pushing stacked PRs to GitHub, link them with gh stack link so GitHub recognizes the stack. gh stack link cannot set PR titles or descriptions, so push the bookmarks with jj git push and create the PRs with gh pr create first, then run gh stack link with the bookmarks or PR numbers in stack order, from bottom to top. It reuses the existing PRs and links them as a stack. Do not use other gh stack commands; jj manages the stack locally.
